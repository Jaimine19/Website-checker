1. Abstract

Abstract Web security misconfiguration remains one of the most prevalent and preventable categories of vulnerability affecting public-facing websites. This project presents Website Security Checker, a browser-based tool built with Python and Streamlit that performs a real-time, fully passive audit of any publicly accessible website and assigns it an A–F security grade out of 100 points. The tool evaluates seven industry-standard security indicators — HTTPS adoption, HTTP-to-HTTPS redirect enforcement, SSL/TLS certificate validity, and the presence of four critical HTTP security response headers (HSTS, CSP, X-Frame-Options, and X-Content-Type-Options). All checks are non-intrusive: no exploits, fuzzing, or authentication probing are attempted. The system incorporates multiple server-side safety controls, including SSRF protection, port allowlisting, per-hop redirect revalidation, network timeouts, and result caching, making it suitable for public deployment. Results are presented via a custom dark-themed UI with shareable URLs, downloadable plain-text reports, and a side-by-side comparison mode for two websites. The tool serves as both a diagnostic utility for developers and site owners and an educational resource for understanding foundational web security practices.

2. Introduction

The web continues to be the primary surface through which users interact with services, commerce, and information. Despite widespread awareness of security best practices, a significant proportion of websites still fail to implement basic protections — leaving users exposed to network eavesdropping, certificate spoofing, cross-site scripting, and clickjacking attacks.

Most professional security scanning tools are either expensive, require installation, or demand technical expertise to interpret. There is a clear need for a simple, zero-friction tool that any developer, student, or website owner can use to instantly understand the security posture of a site without any setup or specialist knowledge.

This project addresses that need by delivering a self-contained Streamlit web application that accepts a URL, performs a set of passive checks within seconds, and presents findings as a scored, graded, plain-English report. The application is accessible from any browser, requires no account or login, and is safe to run on a public server.

3. Objectives

  • Provide instant, zero-setup security grading for any public website.
  • Evaluate seven foundational security checks covering transport security, certificate health, and HTTP security headers.
  • Present results in plain English with clear explanations of why each check matters.
  • Support side-by-side comparison of two websites to aid competitive analysis and benchmarking.
  • Generate shareable, bookmarkable result URLs and downloadable plain-text reports.
  • Ensure the tool itself cannot be used as an attack vector (SSRF protection, port restrictions, rate limiting).
  • Serve as an educational resource that helps developers understand and remediate common security gaps.

4. Scope & Limitations

In Scope

  • Passive, read-only HTTP/HTTPS requests to publicly accessible websites
  • SSL/TLS certificate inspection (validity, expiry, issuer) via direct TLS handshake
  • HTTP response header analysis for four security headers
  • HTTPS adoption and HTTP-to-HTTPS redirect detection

Out of Scope

  • Authentication-gated pages or pages requiring session cookies
  • Vulnerability scanning, fuzzing, or exploit testing of any kind
  • Application-layer checks (SQL injection, XSS payloads, CSRF tokens)
  • DNS security (DNSSEC), email security (SPF/DKIM/DMARC), or server configuration audits
  • Internal / private network hosts (blocked by design)
Note: A grade of A does not guarantee a site is fully secure. A grade of F does not mean a site has been compromised. This tool measures a specific, well-defined subset of security hygiene.

6. System Architecture

The application is a single-file Streamlit app (code.py, ~1,060 lines) structured into five clearly separated logical layers:

LayerComponentsResponsibility
Types & Config CertResult, constants TypedDict for certificate results; timeout, cache, redirect, and header registry settings
Safety Guards resolve_public_ips(), validate_url() Block SSRF, private IPs, non-standard ports, and invalid schemes before any network call
Scan Engine fetch(), check_http_redirect(), check_certificate() Execute individual network probes and return structured results
Scoring Engine build_checks(), make_check(), grade_for(), run_scan() Aggregate probe results into scored check dicts, compute total score and letter grade; cached
UI Layer APP_CSS, show_intro(), show_results(), show_comparison(), main() Custom CSS theming, hero banner, tab routing, check card rendering, report download

Data flows as follows: main() → run_scan() → fetch() + check_http_redirect() + check_certificate() → build_checks() → grade_for() → show_results().

7. Security Checks & Scoring Methodology

Seven checks are run on every scan. Each check produces a pass, warn, or fail status and contributes a fixed number of points to the total score out of 100.

#CheckMax PtsPass ConditionSecurity Rationale
1Uses HTTPS20 Final URL scheme is https:// Encrypts all traffic; prevents eavesdropping, injection, and man-in-the-middle attacks
2HTTP → HTTPS Redirect10 http:// request returns 3xx redirect to https:// Ensures visitors who type plain HTTP are automatically protected
3Valid SSL Certificate20 Trusted cert, ≥15 days to expiry (10 pts if expiring soon) Expired or untrusted certs break browser trust and expose users to interception
4Strict-Transport-Security (HSTS)15 strict-transport-security header present Instructs browsers to always use HTTPS for the domain; prevents SSL-stripping attacks
5Content-Security-Policy (CSP)15 content-security-policy header present Controls which scripts and resources may load; primary XSS defence
6X-Frame-Options10 Header present, or CSP contains frame-ancestors Prevents embedding the page in a foreign iframe (clickjacking)
7X-Content-Type-Options10 x-content-type-options header present Disables MIME-type sniffing; prevents browsers executing misidentified content

Grade Scale

A  ·  90 – 100
B  ·  75 – 89
C  ·  60 – 74
D  ·  40 – 59
F  ·  0 – 39

8. Safety & Abuse-Prevention Design

Because the application makes outbound HTTP/S requests on behalf of users, it is itself a potential vector for Server-Side Request Forgery (SSRF) and abuse. The following controls are implemented:

ThreatControlImplementation Detail
SSRF / internal network access All resolved IPs verified as globally routable resolve_public_ips() uses ipaddress.ip_address.is_global to reject RFC 1918, loopback, link-local, and multicast addresses
Non-standard port abuse Port allowlist: 80 and 443 only validate_url() raises ScanError for any other port value
Malicious redirect chains Every redirect hop re-validated fetch() calls validate_url() on every Location header before following
Infinite redirect loops Hard cap of 5 redirects MAX_REDIRECTS = 5; loop raises ScanError after the limit
Slow / hanging hosts 6-second network timeout TIMEOUT = 6 passed to all requests.get() and socket.create_connection() calls
Scan hammering / DoS from UI 3-second cooldown between scans COOLDOWN_SECONDS = 3 checked against st.session_state["last_scan"]
Repeated identical requests 120-second result cache @st.cache_data(ttl=120) on run_scan(); same input served from cache

9. User Interface & Features

Theme & Styling

The UI uses a custom dark cybersecurity theme (~340 lines of embedded CSS). The hero banner features a gradient dark background, a shimmer-animated gradient title, and a stats strip showing checks run, max score, grade scale, and attacks sent. The Inter and JetBrains Mono fonts are loaded for display and code elements respectively.

Single-Site Scan Tab

  • Text input accepts bare hostnames (e.g. github.com) or full URLs
  • On submit: spinner shown, run_scan() called, result stored in session state
  • Result renders a grade badge, score bar, per-check cards (✅ / ⚠️ / ❌), and a download button
  • Successful scans update the browser URL with ?site=<host> for shareability

Compare Two Sites Tab

  • Two text inputs side-by-side; both sites scanned in parallel spinners
  • Results rendered as a detailed comparison table with per-check winner highlighting
  • Downloadable side-by-side comparison report in plain text

Sidebar

  • Grade scale reference table always visible
  • Disclaimer that only passive checks are performed

Downloadable Reports

Both scan modes offer a plain-text download button. The single-site report lists every check with status, points, and detail. The comparison report formats both sites in aligned columns for easy side-by-side reading.

11. How to Run

Prerequisites

  • Python 3.9 or later (tested on 3.12)
  • pip

Installation

pip install -r requirements.txt

Launch

python -m streamlit run code.py

The application starts at http://localhost:8501 and opens automatically in the default browser. The server keeps running until the terminal window is closed.

12. Results & Discussion

The tool successfully performs all seven checks within the 6-second timeout window for the vast majority of responsive public websites. Key behavioural observations:

  • HTTPS adoption: Most major websites (Google, GitHub, IBM) achieve full marks on HTTPS and certificate checks, earning A grades overall.
  • Header gaps are common: CSP and HSTS are the most frequently missing headers, even on otherwise well-configured sites, and are the primary differentiator between A and B grades.
  • X-Frame-Options equivalence: The tool correctly handles the modern pattern where frame-ancestors in a CSP replaces the older X-Frame-Options header, avoiding false failures.
  • Caching effectiveness: The 120-second @st.cache_data cache significantly reduces redundant network calls when multiple users scan the same site within the window.
  • SSRF protection: All tested attempts to scan private addresses (e.g. 192.168.1.1, localhost) are correctly blocked with a user-friendly error message.

13. Conclusion & Future Work

Website Security Checker delivers on its core goal: a zero-setup, browser-accessible tool that produces an understandable, actionable security grade for any public website within seconds. Its layered safety architecture ensures it cannot be weaponised against internal infrastructure, and its Streamlit-based UI makes findings accessible to non-technical users.

Potential Future Enhancements

  • Additional headers: Add checks for Permissions-Policy, Referrer-Policy, and Cross-Origin-* headers
  • DNSSEC / CAA records: Extend DNS checks to include DNSSEC validation and Certification Authority Authorization records
  • Email security: Add SPF, DKIM, and DMARC record checks for the scanned domain
  • Historical tracking: Store scan results in a lightweight database to show grade trends over time
  • PDF export: Utilise the existing reportlab dependency to generate a formatted PDF report in addition to the plain-text download
  • API mode: Expose scan results as a JSON REST endpoint for CI/CD pipeline integration
  • Rate limiting per IP: Move cooldown enforcement to server-side middleware for multi-user deployments
